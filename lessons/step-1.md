## Хочу

Сайт `devops-aws-waf` получает согласованный каркас из пятнадцати названных разделов в навигации всех четырёх языков (`ru/`, `en/`, `uk/`, `de/`), развёрнутую посадочную страницу `ru/index.html` и пять полностью написанных содержательных глав `ru/01.html` - `ru/05.html`, закладывающих фундамент архитектуры AWS WAFv2:

- 01: Архитектура и WCU (Web ACL, правила, группы правил, модель емкости WCU 1500/5000, порядок выполнения, Default Action).
- 02: Области и ассоциации (Scope CLOUDFRONT в us-east-1 против REGIONAL: ALB, API Gateway REST/HTTP, AppSync GraphQL, Cognito User Pools, AWS Verified Access).
- 03: Управляемые правила (AWS Managed Rules - AMR: Core Rule Set, Known Bad Inputs, Amazon IP Reputation, SQLi, Linux/POSIX OS, PHP rules, версионирование и rolling updates).
- 04: Кастомные правила (IP Sets IPv4/IPv6 CIDR, Regex Pattern Sets, Geo Match, String Match, Size Constraints и заголовки).
- 05: Условия и агрегация (Rate-based правила, агрегация по IP / HTTP-заголовкам / Query / Cookies, логические операторы AND/OR/NOT, Scope-down statements и текстовые трансформации).

Каждое утверждение об инструменте, вынесенное на эти страницы, доказывается выполнением на хосте без обращения к живой сети AWS: структуры JSON, допустимые диапазоны, типы ресурсов и значения перечислений берутся из `aws wafv2 ... --generate-cli-skeleton`, локального разбора `jq` и расчёта `python3`. Страницы 06-15 остаются честными скелетами с реальными названиями тем в навигации: нумерация и пейджер работают корректно.

## Предикаты

1. **Содержание.** На шести страницах (`ru/index.html`, `ru/01.html` - `ru/05.html`) отсутствуют строки-заглушки («Текст этого раздела ещё не написан»); объём `data-words` посадочной не менее 1800 слов, каждой из тем 01-05 - не менее 1000 слов; каждый содержательный заголовок `<h2>` этих тем несёт двухуровневую нумерацию вида `N · Название` с якорной ссылкой, а блоки «Главная мысль страницы» и «Артефакты» остаются без номера; в навигации на всех страницах всех четырёх языков установлены пятнадцать настоящих названий разделов вместо шаблона «Раздел N».
2. **Утверждения.** В `tools/claims.tsv` объявлено не менее двенадцати утверждений, относящихся к темам 01-05, каждое снабжено рабочей командой; `./tools/check-claims.sh` печатает `ЗЕЛЁНОЕ` и ни одной строки со словом `НЕТ`. Ни одна команда не обращается к живому AWS: разрешены только `--generate-cli-skeleton`, локальный разбор `jq` и счёт `python3`.
3. **Целостность.** `git diff` шага не выходит за пределы `ru/*.html`, `en|uk|de/*.html` (только названия навигации от генератора и заголовки в карточках-заглушках), `index.html`, `sitemap.xml`, `site.conf`, `tools/claims.tsv` и `lessons/`; файлы `assets/` и `tools/` кроме `claims.tsv` не изменены ни одной строкой. Полный запуск `./check.sh` отвечает `ЗЕЛЁНОЕ`, и каждая строка его сводки говорит `ДА`; время и состав проверок зафиксированы в записи шага.

## Границы

1. **Разделы 06-09 не пишутся.** Они составляют территорию действий правил, защиты от ботов, потокового логирования и FinOps/аудита и передаются в Шаг 2 (Батч 2) согласно пакетной модели разработки (`AGENTS.md` §5.15).
2. **Практические примеры 10-12 (Noob / Pro / IGL) не пишутся.** Они требуют по 6-9 отработанных боевых сценариев на уровень и сдаются отдельным пакетом в Шаге 3 (Батч 3).
3. **Банки вопросов 13-15 (Noob / Pro / IGL), навигатор (`navigator.html`) и словарь (`glossary.html`) не пишутся.** Канонический порядок синтеза (`AGENTS.md` §5.17) запрещает делать словарь раньше навигатора, а навигатор раньше вопросов. Уходят в Шаг 4 (Батч 4).
4. **Разметка терминов (`.term`) не устанавливается.** Она связана со словарём двусторонним контрактом и до его создания бессмысленна. Уходит в Шаг 4.
5. **Схемы (inline SVG) не внедряются.** Текст страниц самодостаточен без схем; схемы усиливают материал на финальном этапе (Шаг 5) строго по Правилу 26.
6. **Английский, украинский и немецкий остаются заглушками.** Русский язык утверждён Кондуктором как основной; карточки-заглушки честно направляют на русскую версию страниц (`AGENTS.md` §5.20).
7. **Ни одна проверка не обращается к живому AWS.** Доступа к живому облаку у сайта нет; проверяются только структуры CLI, спецификации и числовые лимиты.

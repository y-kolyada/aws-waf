## 1. Что сделано

В рамках шестого шага выполнен глубокий визуальный и структурный рефакторинг всех 17 SVG-диаграмм курса и их исходников Mermaid в ответ на критическое замечание Архитектора о монотонности и однообразии схем на курсах серии («близнецы-братья»).

Вместо примитивных вертикальных стеков «прямоугольник под прямоугольником» разработаны 17 принципиально различных архитектурных топологий, отражающих внутреннюю инженерную механику каждого раздела:

1. **`ru/index.html` (Схема 1 · Периметровая карта эшелонированной защиты / Two-Plane Boundary Map):** Разветвление входящего трафика от CloudFront Edge PoP на два независимых региональных шлюза (ALB и API Gateway в VPC) с параллельным контуром защиты от DDoS через AWS Shield Advanced.
2. **`ru/01.html` (Схема 2 · Ступенчатый каскад приоритетов с измерителем емкости WCU / Stepped Waterfall with Gauge Meter):** Левая сторона визуализирует лестничный каскад обработки правил (P=0, P=10, Default Action), правая сторона представляет собой вертикальную измерительную колонку лимита емкости правил (711/1500 WCU).
3. **`ru/02.html` (Схема 3 · Двухколонная сравнительная модель областей видимости / Dual-Scope Comparative Columns):** Четкое пространственное разделение глобальной области (Global Scope CloudFront в регионе us-east-1) и региональной области (Regional Scope ALB / APIGW / Cognito) с указанием различий CLI флагов.
4. **`ru/03.html` (Схема 4 · Трехколонный компонентный разбор стратегий управления / 3-Pillar Rule Handling Breakdown):** Разветвление верхнего блока Web ACL на три независимых столпа обработки правил: 1. Прямая блокировка (Default Block), 2. Аудит через Override to Count, 3. Исключение шумных правил через ExcludedRules.
5. **`ru/04.html` (Схема 5 · Четырехуровневая воронка инспекции пакета / 4-Tier Inspection Funnel Stack):** Сужающийся послойный стек глубокого анализа запроса: FieldToMatch (селектор) -> Text Transformation (нормализация) -> Predicates Grid (условия) -> Boolean Combinator (логическая связка).
6. **`ru/05.html` (Схема 6 · Кольцевой цикл скользящего окна rate-limiting с обратной связью / Circular Sliding Window Loop):** Замкнутый рециркуляционный контур: Входящие запросы -> Скользящее окно 300с -> Компаратор лимита -> Блокировка 429 -> Автоматический возврат в окно по истечении тайм-аута.
7. **`ru/06.html` (Схема 7 · Трехколоночная классификация вердиктов правил / 3-Pillar Action Verdict Split):** Классификация исходов инспекции на три категории: терминальные действия (Allow / Block), метрические действия без прерывания (Count / Label) и интерактивные клиентские вызовы (CAPTCHA / Challenge).
8. **`ru/07.html` (Схема 8 · Протокольная диаграмма последовательности Silent Challenge / Protocol Sequence Ladder):** Две вертикальные оси (Клиентский браузер с WAF JS SDK и AWS WAF Edge) с четырьмя строго горизонтальными шагами рукопожатия: запрос без токена, возврат скрипта 202 Accepted, выполнение телеметрии браузера и повторный запрос с валидным токеном `x-amzn-waf-action-token`.
9. **`ru/08.html` (Схема 9 · Радиальная звезда телеметрии / Hub-and-Spoke Telemetry Star):** Центральный движок WAF Streaming Log Engine с четырьмя радиальными стрелками, направленными в целевые приемники телеметрии: CloudWatch Alarms (алерты), Kinesis Firehose (стриминг), CloudWatch Logs (поиск) и S3 Data Lake (долгосрочный аудит в Athena).
10. **`ru/09.html` (Схема 10 · Четырехуровневая пирамида жизненного цикла внедрения / 4-Tier Rollout Lifecycle Pyramid):** Пирамидальная модель безопасной выкатки правил безопасности: широкое основание Count Mode (сбор базовых метрик) -> Sampled Requests Audit -> Canary Rollout 10% -> Enforce Block 100%.
11. **`ru/10.html` (Схема 11 · Серпантинная дорожка эшелонированного периметра / Serpentine Stepping Stones Roadmap):** Извилистый маршрут прохождения запроса через последовательные защитные рубежи: Белый список IP -> Гео/Tor фильтрация -> Core Rule Set -> Ограничение размера тела -> Изоляция админки /admin.
12. **`ru/11.html` (Схема 12 · Матрица квадрантов безопасности 2x2 с центральным ядром / 2x2 Security Quadrant Grid with Pro Hub):** Центральный блок Pro Architecture окружен четырьмя квадрантами: JWT Rate Limiting (сверху-слева), ATP Antifraud (сверху-справа), PII Redaction в логах (снизу-слева) и CI/CD Terraform Gates (снизу-справа).
13. **`ru/12.html` (Схема 13 · Замкнутый контур автоматического реагирования SOAR / Closed-Loop Autonomous SOAR Cycle):** Архитектура автореагирования с петлей обратной связи: L7 Атака -> WAF Логи -> Amazon EventBridge -> AWS Lambda / Athena -> Динамическое добавление атакующего CIDR в WAF IPSet -> Мгновенная нейтрализация на периметре.
14. **`ru/13.html` (Схема 14 · Иерархическое дерево компетенций Noob / Hierarchical Competency Branch Tree):** Корневой узел фундаментальной подготовки Junior Cloud Security Engineer с расходящимися ветвями к 5 тематическим блокам квалификационных вопросов.
15. **`ru/14.html` (Схема 15 · Сетевая паутина инженерных областей Pro / Multi-Tier Competency Network Mesh):** Центральное ядро квалификации Pro, связанное двунаправленными гранями со специализированными областями: Bot Control, ATP Antifraud, Kinesis Streaming, Custom Rules и Terraform IaC.
16. **`ru/15.html` (Схема 16 · Корпоративная иерархическая пирамида управления IGL / Multi-Tier Enterprise Governance Tree):** Двухуровневое дерево управления масштабом Enterprise: AWS Organizations + Firewall Manager Admin на верхнем уровне с веерным применением политик Web ACL к аккаунтам Core Services, Production Workloads и Dev/Sandbox.
17. **`ru/navigator.html` (Схема 17 · Радиальная матрица 3x3 девяти инженерных линз / Radial 3x3 Lenses Matrix):** Центральный блок ядра Web ACL Core Engine, окруженный радиальной сеткой из 9 канонических инженерных линз навигатора курса.

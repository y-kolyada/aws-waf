## Хочу

Полный комплект из 17 архитектурных векторных схем курса `devops-aws-waf` кардинально дифференцируется по своей пространственной геометрии и топологическим архетипам:

1. **Устранение однотипных вертикальных цепочек:** Каждая страница получает схему со своей уникальной топологией, отражающей архитектурную логику темы:
   - `ru/index.html` (Схема 1): Периметровая карта эшелонированной защиты (CloudFront PoP -> dual VPC ALB/APIGW -> Shield Advanced).
   - `ru/01.html` (Схема 2): Ступенчатый каскад приоритетов (слева) с вертикальной шкалой емкости WCU (справа: 711/1500 WCU).
   - `ru/02.html` (Схема 3): Двухколонная сравнительная модель областей видимости (Global Scope CloudFront vs Regional Scope ALB/APIGW/Cognito).
   - `ru/03.html` (Схема 4): Трехколонный разбор стратегий управления группами правил (1. Block, 2. Override Count, 3. ExcludedRules).
   - `ru/04.html` (Схема 5): Четырехуровневая воронка инспекции пакета (FieldToMatch -> Normalization -> Predicates Grid -> Boolean Combinator).
   - `ru/05.html` (Схема 6): Кольцевой цикл скользящего окна rate-limiting с обратной связью (Requests -> Sliding Window -> Comparator -> Block -> Recovery).
   - `ru/06.html` (Схема 7): Трехколоночная классификация вердиктов (Terminal Allow/Block, Metric Count, Interactive Challenges CAPTCHA/Challenge).
   - `ru/07.html` (Схема 8): Протокольная диаграмма последовательности рукопожатия Silent Challenge (Клиентский браузер с JS SDK vs AWS WAF Edge).
   - `ru/08.html` (Схема 9): Радиальная звезда («Hub-and-Spoke») телеметрии (Центральный движок логов -> Alarms, Firehose, CW Logs, S3/Athena).
   - `ru/09.html` (Схема 10): Четырехуровневая пирамида жизненного цикла внедрения (Count -> Sampled Audit -> Canary -> Enforce Block).
   - `ru/10.html` (Схема 11): Серпантинная дорожка («Stepping Stones») эшелонированного периметра (IP Allowlist -> Tor/Geo -> CRS -> Size Limit -> /admin).
   - `ru/11.html` (Схема 12): 2x2 матрица квадрантов безопасности с центральным ядром Pro (JWT Rate Limiting, ATP Antifraud, PII Redaction, Terraform Gates).
   - `ru/12.html` (Схема 13): Замкнутый контур автоматического реагирования SOAR с петлей обратной связи (L7 Attack -> EventBridge -> Lambda/Athena -> Dynamic IPSet Ban -> Mitigation).
   - `ru/13.html` (Схема 14): Иерархическое дерево компетенций уровня Noob с ветвлением на 5 тематических кластеров.
   - `ru/14.html` (Схема 15): Сетевая паутина (Mesh) инженерных областей уровня Pro вокруг центрального ядра компетенций.
   - `ru/15.html` (Схема 16): Многоуровневое иерархическое дерево корпоративного управления уровня IGL (AWS Organizations + FMS Admin -> Core/Prod/Dev).
   - `ru/navigator.html` (Схема 17): Радиальная матрица 3x3 девяти инженерных линз вокруг центрального ядра Web ACL.

2. **Сохранение математической строгости Правила 26 и чекера `check-diagrams.mjs`:**
   - Все 17 схем имеют `viewBox="0 0 320 H"` ($H \in [220, 240]$) и `style="max-width:320px;height:auto;display:block;margin:0 auto"`.
   - Зазоры текстовых подписей до границ рамок строго `>= 6px`, длина стрелок `>= 6px` (для развилок ножки `>= 7px`).
   - Все стрелки ортогональны при развилках, начинаются на границах блоков и наконечниками касаются целевых рамок; изолированные блоки отсутствуют.

3. **Синхронизация исходников и каталога:**
   - Все 17 файлов `.mmd` в каталоге `diagrams/` и каталог `diagrams/README.md` приведены в строгое соответствие с новой топологией.

## Предикаты

1. **Топологическое разнообразие и актуализация Mermaid.** Все 17 схем на 17 страницах (`ru/index.html`, `ru/01.html`..`ru/15.html`, `ru/navigator.html`) имеют отличную друг от друга геометрию и топологические структуры (ни одна схема курса не повторяет структуру другой); каталог `diagrams/` содержит 17 синхронизированных файлов `.mmd`, а `diagrams/README.md` отражает обновленные топологии.
2. **Нулевой брак в `tools/check-diagrams.mjs`.** Скрипт валидации схем `node tools/check-diagrams.mjs` завершается со статусом `ЗЕЛЁНОЕ`, проверяя 17 схем на 17 страницах при 0 дефектов геометрии, 0 дефектов зазоров и 0 изолированных элементов.
3. **Безупречный прогон сквозного аудита `./check.sh`.** Полный контрольный прогон `./check.sh` завершается за один проход с вердиктом `ЗЕЛЁНОЕ` (15/15 проверок со статусом `[ ДА ]`); изменения зафиксированы локальными коммитами в ветке `dev` без `git push` и без merge в `prod`.
